## Check Dependencies

Ensure you have your required dependencies, which Next.js and React should already satisfy:

- [x] `next` (App Router *only* — Pages Router is not supported.)
- [x] `react` and `react-dom`
- [x] `@supabase/supabase-js`
- [x] `@supabase/ssr` (cookie sessions for Google admin login)

From your terminal at your application project root run:

```bash
npm ls next react react-dom @supabase/supabase-js @supabase/ssr
```

::: {.callout}
# Missing packages print as `(empty)`. 

That is fine for the Supabase packages — install them in the next step. 

If `next`, `react`, or `react-dom` are missing, add them (or scaffold with `create-next-app`) before continuing.

:::

## Installing

### Install Guestbook Package

Via the terminal from your existing Next.js app root call:

```bash
npm install y2k-guestbook @supabase/supabase-js @supabase/ssr
```

## Configuring the Application

::: {.callout}
# The package ships the user interface, server actions, settings, CSS layer, auth handlers, and ready-made page entrypoints. 

Next still only loads routes and `proxy.ts` from *your* project, so the steps below are thin re-exports and one layout mount.

:::

### Protect Admin Login

Next only runs auth/session files from *your* project root. Add three small re-exports:

::: {.tabset}

# proxy.ts

Create `proxy.ts` at your app root to keep the Supabase session fresh and block `/admin` unless `app_metadata.role === "admin"`:

```typescript
export { proxy, config } from "y2k-guestbook/proxy";
```

- The **admin login** link stays visible, but users without proper access are booted back to the 
public guestbook comment board and presented with an error.
- Error message copy is hardcoded in [`components/_shared/AdminAuthErrorOverlay.tsx`](https://github.com/beck-chan/y2k-guestbook/blob/main/components/_shared/AdminAuthErrorOverlay.tsx){.blank} — not accessible through the admin dashboard settings.

::: {.callout}

If you already have a `proxy.ts`, import `{ proxy as guestbookProxy }` from `y2k-guestbook/proxy` and call it from your existing `proxy` function instead of replacing the file. Keep `/auth/callback` and `/admin/login` reachable.

:::

# app/admin/login/route.ts

Create `app/admin/login/route.ts`, which starts Google sign-in:

```typescript
export { GET } from "y2k-guestbook/admin-login";
```

CLicking **admin login** sends you to Google sign-in. After authenticating, you return to the your configured `${SITE_URL}/auth/callback`.

# app/auth/callback/route.ts

Create `app/auth/callback/route.ts`, which finishes login and sends you to the right page after Google:

```typescript
export { GET } from "y2k-guestbook/callback";
```

:::

### Add Guestbook Pages

Next only serves pages from *your* `app/` folder. Re-export the packaged entrypoints:

::: {.tabset}

# Public Comment Board

Create `page.tsx` for your public guestbook comment board where you want it to live:

```typescript
export {
  GuestbookPublicPage as default,
  guestbookPublicMetadata as metadata,
} from "y2k-guestbook";
```

After you create the public comment board, set matching `homeHref` for the admin dashboard. 

# Admin Dashboard

Create your admin dashboard where you want it to live. Default path is `app/admin/page.tsx`:

```typescript
import {
  GuestbookAdminPage,
  guestbookAdminMetadata,
} from "y2k-guestbook";

export const metadata = guestbookAdminMetadata;

export default function AdminPage({
  searchParams,
}: {
  searchParams: Promise<Record<string, string | string[] | undefined>>;
}) {
  return (
    <GuestbookAdminPage
      searchParams={searchParams}
      homeHref="/"
    />
  );
}
```

To customize the path for the admin dashboard:

{/* INSERT HERE */}

Set `homeHref=` according to where your public comment board lives:

- `app/page.tsx` — When the guestbook *is* the site, then use `homeHref="/"`.
- `app/guestbook/page.tsx` — When `/` (root) is already your site, then use `homeHref="/guestbook"`.

## Configure Next.js

::: {.tabset}

# i. Wrap Config

Next needs a small config wrap so it can compile the shipped npm package, and so the **view example** link for the custom theme Settings can serve a sample CSS file.

In your `next.config.ts` (or `next.config.js`), wrap your existing config with `withGuestbookConfig`:

```typescript
import type { NextConfig } from "next";
import { withGuestbookConfig } from "y2k-guestbook/config";

const nextConfig: NextConfig = {
  // your existing options
};

export default withGuestbookConfig(nextConfig);
```

::: {.callout}  
If you already define your own `rewrites()`, merge them carefully — `withGuestbookConfig` adds one rewrite of its own.

:::

# ii. Set Theme Example Route

Create `app/admin/example/route.ts`: 

```typescript
export { GET, dynamic } from "y2k-guestbook/example-css";
```

This is the file that **view example** loads — it only works after the config wrapping.

# iii. Add Stylesheet and Providers

Place two last pieces in your root layout (`app/layout.tsx`):

1. Import the default guestbook stylesheet (`y2k-guestbook/styles.css`) so the board and admin dashboard have the skeleton theme. Leave your own Tailwind import in `globals.css` as-is.

2. Wrap the app in `GuestbookProviders`. That turns on settings, custom theme overrides, and the admin auth error overlay.

```typescript
import type { Metadata } from "next";
import "y2k-guestbook/styles.css";
import { GuestbookProviders } from "y2k-guestbook";

export const metadata: Metadata = {
  title: "y2k guestbook",
  description: "Sign the guestbook.",
};

export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    <html lang="en" className="h-full antialiased">
      <body className="min-h-full">
        <GuestbookProviders>{children}</GuestbookProviders>
      </body>
    </html>
  );
}
```

::: {.callout}
If you already have a root layout, merge these in: import the stylesheet once, and wrap `{children}` with `GuestbookProviders`.

:::
