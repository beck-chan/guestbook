# Prerequisites

Installing the application ships the guestbook user interface and default Supabase wiring.

You'll need to first:

- [ ] Install Node.js.
- [ ] Configure a Supabase project. 
- [ ] Hook up Google OAuth 2.0 to enable admin.

::: {.callout}
This guide assumes:

- [x] You're familiar with using your development terminal and the command line interface (CLI).
- [x] You already have a GitHub and Google account, and know your way around the former.
- [x] You already have a way to deploy your application. These docs cover using Vercel.
:::

## Install Node.js with npm

Install from [nodejs.org](https://nodejs.org){.blank}, or via your terminal for a recommended version:

::: {tabset}

# nvm

```bash
nvm install 22
nvm use 22

# Confirm that you have the right versions
node -v
npm -v
```

# fnm

```bash
fnm install 22
fnm use 22

# Confirm that you have the right versions
node -v
npm -v
```

:::

::: {.callout}
Use **Node.js 20 LTS** or **22 LTS** (either includes `npm`). Next.js `16` needs `18.18+`; `20+` is the safer default.

:::

## Hook up Google OAuth 2.0

{/* Admin login is **Sign in with Google**. Skip billing prompts. Scopes are only `openid`, `email`, and `profile`.

In [Google Cloud Console](https://console.cloud.google.com/):

1. Create a Cloud project. Configure the **OAuth consent screen** (External). While the app is in **Testing**, add your Gmail as a test user.
2. Create an OAuth client → **Web application**.
3. **Authorized JavaScript origins:** `http://localhost:3000` (add the Vercel / live origin when you deploy).

5. Save the Client ID and Client secret for the Supabase Google provider.

::: {.callout}

Enabling Google lets **anyone with a Google account** finish OAuth unless you gate it. Turning off “Allow new users to sign up” blocks email signup; it does **not** reliably stop first-time Google logins. The starter rejects unknown emails **before** insert (`admin_allowlist` + Before User Created). A non-allowlisted Google account creates **no** `auth.users` row.

::: */}
