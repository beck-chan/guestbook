# Add Analytics

Use PostHog to track page views and user interactions, as well as to show a visitor hit counter.

::: {.callout}
This guide assumes:

- [x] You've set up the guestbook application with either [Quickstart](/docs/quickstart) or [Install via npm](/docs/install).
- [x] You already have a PostHog account and project.
:::

## Retrieve PostHog Variables

From the [PostHog](https://posthog.com/){.blank} dashboard's left sidebar, click **Settings**:

::: {.tabset}

# i. Retrieve Project Details

 Under Settings - General:

1. Copy your **Project token**. Enter this into your `.env.local` file under your `NEXT_PUBLIC_POSTHOG_KEY`:
    
    ```bash
    NEXT_PUBLIC_POSTHOG_KEY=<your-project-token>
    ```

2. Under SDK setup, grab the `api_host` value from one of the snippets (For example, `https://us.i.posthog.com`). Enter this into your `.env.local` file under your `NEXT_PUBLIC_POSTHOG_HOST`:
    
    ```bash
    NEXT_PUBLIC_POSTHOG_HOST=<your-project-api-host>
    ```

3. Copy your **Project ID**. Enter this into your `.env.local` file under your `POSTHOG_PROJECT_ID`:
    
    ```bash
    POSTHOG_PROJECT_ID=<your-project-id>
    ```

# ii. Create Personal API Key

1. In the Settings left sidebar, select **Personal API keys** under Account.

2. Click **+ Create personal API key**.

    a. Give the key a **Label**. For example: `Guestbook Hit Counter`
    b. Under **Organizations & project access**, select **Projects** then the project you want to grant access to.
    c. Under **Scopes**, select **Query**: `Read`.
    d. Click **Create key**.

3. Copy your API key after it generates. Enter this into your `.env.local` file under your `POSTHOG_PERSONAL_API_KEY`:

    ```bash
    POSTHOG_PERSONAL_API_KEY=<your-personal-api-key>
    ```

4. For your `POSTHOG_API_HOST`, enter the app host for the Query API (For example: `https://us.posthog.com`, not the `*.i.posthog.com` ingest host):
    
    ```bash
    POSTHOG_API_HOST=<your-api-host>
    ```

:::

## Enable Hit Counter

1. Ensure `.env.local` includes the Query API values from **Retrieve PostHog Variables**:

    ```bash
    POSTHOG_PERSONAL_API_KEY=<your-personal-api-key>
    POSTHOG_PROJECT_ID=<your-project-id>
    POSTHOG_API_HOST=<your-api-host>
    ```

2. Show or hide the counter with `flags.hitCounter` in `lib/flags.ts` (default `true`).

3. On the public guestbook page, `HitCounter` mounts once (Quickstart: `app/page.tsx`; npm: `import { HitCounter } from "y2k-guestbook"` as in [Install via npm](/docs/install)).

The digits are unique `$pageview` visitors from PostHog’s Query API. In production they live-update: +1 on a browser’s first visit, then poll about every 45 seconds, and never tick down.

::: {.callout}
`npm run dev` keeps the decorative fallback (`000481`) and does not call PostHog. For live digits, run `npm run build` then `npm run start`, or deploy (for example on Vercel) with the Query API env vars set.
:::

## Enable Web Tracking

1. Copy the example client entry to the **app project root** (next to `app/`):

    ```bash
    cp instrumentation-client.ts.example instrumentation-client.ts
    ```

    Next.js only loads the exact filename `instrumentation-client.ts`. Do not paste the PostHog HTML snippet into your layout.

2. The example initializes PostHog only when `NODE_ENV === "production"`, with `person_profiles: "always"` (pageviews, clicks, and session replay via the SDK defaults).

3. In your PostHog project, enable **Session replay**.

4. Restart after changing env vars or the instrumentation file.

::: {.callout}
`npm run dev` does not send events. Use `npm run build` then `npm run start`, or a production deploy, to capture traffic.
:::
