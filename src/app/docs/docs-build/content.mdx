# Documentation Build

::: {.callout}
# Docs are compiled by [`@next/mdx`](https://www.npmjs.com/package/@next/mdx){.blank}.  

- Each documentation guide is a [`page.tsx`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/example/page.tsx){.blank} that imports [`./content.mdx`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/example/content.mdx){.blank} (the actual markdown content). 
- [`src/app/docs/layout.tsx`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/layout.tsx){.blank} defines the custom layout, side navigation, and docs-only theme. 
:::

## Docs-Only Build

Our custom `npm run docs` script starts Next with `FLAG_DOCSONLY=true` so the root `/` redirects into `/docs` and we don't render the guestbook application.

Defined as a [`package.json`](https://github.com/beck-chan/guestbook/blob/main/package.json){.blank} script, `npm run docs` calls [`scripts/docs-dev.mjs`](https://github.com/beck-chan/guestbook/blob/main/scripts/docs-dev.mjs){.blank}, which starts the same `next dev` as `npm run dev`, then sets `FLAG_DOCSONLY=true` on that process:

- [`src/lib/flags.ts`](https://github.com/beck-chan/guestbook/blob/main/src/lib/flags.ts){.blank} reads that environment variable as `flags.docsOnly`. 
- [`next.config.ts`](https://github.com/beck-chan/guestbook/blob/main/next.config.ts){.blank} also lists `FLAG_DOCSONLY` under `.env` so Next can send it to the browser.

## Basics & Custom Theme

Documentation has its own custom theme, separate from the guestbook defined in  [`src/app/docs/docs.css`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/docs.css){.blank}. The custom theme works together with:

::: {.tabset}

# next.config.ts

[`next.config.ts`](https://github.com/beck-chan/guestbook/blob/main/next.config.ts){.blank} registers [`remark-gfm`](https://www.npmjs.com/package/remark-gfm){.blank} (GitHub-flavoured markdown) and our custom [Remark](https://www.npmjs.com/package/remark){.blank} (Markdown parsing and serialization) plugin, which allows:

- Defining subtitle and flag visibility within a YAML frontmatter block
- Using `:::` fences for formatting content 
- Using shortcodes: `{.heart}` ({.heart}) / `{.button}` (button link) / `{.blank}` (`target="_blank"`) 


The Remark plugin also pulls page metadata out of the paired `content.mdx` so `page.tsx` can import it:

- `title` — The `#` heading, which informs the browser tab
- `toc` — `##` / `###` headings, used for the sticky-note table of contents and anchor links
- `frontmatter` — The YAML defined at the top of the page

`next.config.ts` also registers our custom [Rehype](https://www.npmjs.com/package/rehype){.blank} (HTML parsing and serialization) plugin, which:

- Adds `id` to each heading from its text so that anchor links are functional.
- Runs [`rehype-highlight`](https://www.npmjs.com/package/rehype-highlight){.blank} (our themed syntax highlighting) with a small language set we use in the docs.

# src/mdx-components.tsx

[`src/mdx-components.tsx`](https://github.com/beck-chan/guestbook/blob/main/src/mdx-components.tsx){.blank} runs last at render, swapping native MDX tags for custom styled ones, and registering our fence components so that they display correctly:

- `h1` / `h2` / `h3` become `.docs-title` / `.docs-heading` / `.docs-subheading`
- `pre` becomes `DocsCodeBlock`
- `table` gets `.docs-table`
- `li` gets the heart list item icon (or `DocsTaskItem` for `- [x]`, which are interactive!! checkboxes)
- `DocsCallout` becomes a callout box
- `DocsColumns` becomes mobile-responsive columns 
- `DocsTabset` becomes mobile-responsive tabbed or drop-down section

:::

## Documentation Pages

### Landing Page

The main documentation landing page (`/docs`) lives at [`src/app/docs/page.tsx`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/page.tsx){.blank}, and is built by React, not MDX and  hides the sidebar navigation:

- A `.docs-index` wrapper is what switches the layout from a guide to a landing.
- Displayed subtitle is wrapped into a feature flag ([`src/lib/flags.ts`](https://github.com/beck-chan/guestbook/blob/main/src/lib/flags.ts){.blank}) defined in `docsIndexSubtitle`, rendering different text depending on the `FLAG_PUBLIC` value at build time.

This landing page:

- Reads `DOCS_NAV_SECTIONS` from [`_nav/docs-nav-data.ts`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/_nav/docs-nav-data.ts){.blank} (sidebar navigation).
- Keeps `Installation` / `Guides` / `Reference` sections under tilted sticky notes, defined by `LANDING_TITLES`.
- Turns `Etc.` / `Support` into footer buttons.

### Content Pages

Since every guide in documentation is wrapped in [`src/app/docs/layout.tsx`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/layout.tsx){.blank}, the per-page [`page.tsx`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/example/page.tsx){.blank} defines the rest.

# Guide Pages

Articles feature a sidebar inspired by the poetry book pages, and a sticky-note table of contents, courtesy of [`DocsPage`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/_components/DocsPage.tsx){.blank}.

# API Library

The API Library (`/docs/api`) widens the sidebar and replaces the default links with anchors to calls, with no table of contents by skipping import of `DocsPage` on purpose, instead importing [`DocsApiReference`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/_components/DocsApiReference.tsx){.blank}.

:::

## API Library

The API Library is a hybrid page ([`src/app/docs/api/page.tsx`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/api/page.tsx){.blank}) — it first renders content from [`content.mdx`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/api/content.mdx){.blank}, then [`DocsApiReference`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/_components/DocsApiReference.tsx){.blank} embeds our customized [Scalar API](https://scalar.com/){.blank} explorer underneath.

::: {.callout}
# Since I wanted to be able to adjust the public API explorer to allow users to test requests against their own Supabase database instead of my custom or example public builds, I couldn't go with the easy route of using OpenAPI JSON alongside Scalar.

Instead, using Supabase's Data Rest API capabilities, I [generated a TypeScript schema snapshot](https://supabase.com/docs/guides/api/rest/generating-types){.blank} (`database.types*.ts`) for two versions:

1. A private version, reflecting my custom build.
2. A public version, reflecting an example public build.

Then, translated the generated types into an OpenAPI 3.1 document that is what gets embedded in the API Library explorer.

:::

::: {.tabset}

# Schema Translation

Since Scalar only supports OpenAPI 3.1, we need to translate our generated typescript types into an OpenAPI 3.1 document. 

[`loadDatabaseOpenApi.ts`](https://github.com/beck-chan/guestbook/blob/main/src/lib/docs/loadDatabaseOpenApi.ts){.blank} script reads our generated schema, and [`typesToOpenApi.ts`](https://github.com/beck-chan/guestbook/blob/main/src/lib/docs/typesToOpenApi.ts){.blank} translates them, displaying a different version depending on the build:

- `database.types.ts` when `FLAG_PUBLIC` is off (Beck's custom install)
- `database.types-public.ts` when `FLAG_PUBLIC` is on (the packaged public guestbook)

[`layout.tsx`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/layout.tsx){.blank} builds sidebar links from the the `*types.ts` files, but on `/docs/api`, [`DocsSidenav`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/_nav/DocsSidenav.tsx){.blank} swaps the usual docs nav for [`DocsApiNav`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/_nav/DocsApiNav.tsx){.blank}, linking to the inline method and operation anchors within the Scalar API explorer.

# Scalar API Explorer

[`DocsApiReferenceView`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/_components/DocsApiReferenceView.tsx){.blank} loads the [`@scalar/api-reference`](https://www.npmjs.com/package/@scalar/api-reference){.blank} browser bundle from [`/docs/api/scalar-standalone`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/api/scalar-standalone/route.ts){.blank} and renders it into `.docs-api-reference`.

[`scalarConfig.ts`](https://github.com/beck-chan/guestbook/blob/main/src/lib/docs/scalarConfig.ts){.blank} turns Scalar's own theme off (`theme: "none"`) and injects `customCss` that remaps Scalar onto guestbook tokens (`--peony`, `--paper`, `--futura-font`, `--docs-ink`). It also hides Scalar's sidebar and sticky search bar — docs search still opens Scalar's search — and hides **Test Request** unless `FLAG_PUBLIC` or `FLAG_APITEST` is on.

`docs.css` still does the chrome: `.docs-shell:has(.docs-api-reference)` widens the sidenav. On the public build, a project-ID form above the explorer points Test Request at the visitor's Supabase project.
