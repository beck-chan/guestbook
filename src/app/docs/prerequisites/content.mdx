# Prerequisites

Installing the application ships the guestbook user interface and default Supabase wiring.

You'll need to first:

- [ ] Install Node.js.
- [ ] Configure a Supabase project. 
- [ ] Hook up Google OAuth 2.0 to enable admin.

::: {.callout}
This guide assumes:

- [x] You're familiar with using your development terminal and the command line interface (CLI).
- [x] You already have a GitHub and Google account, and know your way around the former.
- [x] You already have a way to deploy your application. These docs cover using Vercel.
:::

## Install Node.js with npm

Install from [nodejs.org](https://nodejs.org){.blank}, or via your terminal for a recommended version:

::: {tabset}

# nvm

```bash
nvm install 22
nvm use 22

# Confirm that you have the right versions
node -v
npm -v
```

# fnm

```bash
fnm install 22
fnm use 22

# Confirm that you have the right versions
node -v
npm -v
```

:::

::: {.callout}
Use **Node.js 20 LTS** or **22 LTS** (either includes `npm`). Next.js `16` needs `18.18+`; `20+` is the safer default.

:::

## Create Supabase Project

::: {.tabset}

# 1. Create Project

Create an account and organization with [Supabase](https://supabase.com/), then on the Create a new project screen:

a. Enter in your **Organization**, **Project name**, and **Database password**.

    Hang on to your **Database password** — we'll need to enter this into your `.env.local` file under your `DATABASE_URL`.

b. Select a **Region**.

c. Under Security, check off:

    - **Enable Data API**
    - **Enable automatic RLS**

    Leave `Automatically expose new tables` *unchecked*.

d. Click **Create new project**.

# 2. Retrieve API Keys

When your project is ready:

a. In the left sidebar, click **Project Settings**, then select **API Keys**.

b. Under Publishable and secret API keys, copy the **Publishable key** to your clipboard. 

    Hang on to this — we'll need to enter this into your `.env.local` file under your `NEXT_PUBLIC_SUPABASE_URL`:

    ```bash
    NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_<your-publishable-key>
    ```

c. Click **Legacy anon, service_role, API keys**, then copy the `service_role` `secret` key to your clipboard. 

    Hang on to this — we'll need to enter this into your `.env.local` file under your `SUPABASE_SERVICE_ROLE_KEY`:

    ```bash
    SUPABASE_SERVICE_ROLE_KEY=<your-service-role-key>
    ```

# 3. Retrieve Supabase URLs

a. In the Settings left sidebar, select **Data API**.

b. Under Overview, copy the **API URL** to your clipboard. 

    Hang on to this — we'll need to enter this into your `.env.local` file and to hook up Supabase and Google OAuth 2.0:

    ```bash
    NEXT_PUBLIC_SUPABASE_URL=https://<your-database-url>.supabase.co
    ```

c. In the top navigation, click the **Connect** button.

d.  Under Connection Method, select **Transaction pooler**. Leave the **Type** as `URI`.

e. Under Connection string, copy the **Shared pooler** to your clipboard. 

    Hang on to this — we'll need to enter this into your `.env.local` file under your `DATABASE_URL`:

    ```bash
    DATABASE_URL=postgresql://postgres.<your-database-url>:[YOUR-PASSWORD]@<your-database-region>.pooler.supabase.com:<port>/postgres
    ```

:::

## Create Google Cloud Project

::: {.callout}
# These instructions assume you are a general Google user with no company or school organization. 

Depending on your Google Cloud organization or setup, you may need to follow different steps. Refer to [Google: Using OAuth 2.0 to Access Google APIs](https://developers.google.com/identity/protocols/oauth2){.blank} for more guidance.
:::

Log in to your [Google Cloud](https://console.cloud.google.com/){.blank} console:

::: {.tabset}

# 1. Create Project

a. [Create a new Google Cloud project](https://developers.google.com/workspace/guides/create-project){.blank}.

b. When the project is ready, select your new project.

c. In the left sidebar, click **APIs & Services**, then select **OAuth consent screen**.

d. In OAuth Overview, click **Get started**.

e. Configure your project, then click **Create**. For example, enter your:

    - App Information
    - Audience (for personal Google accounts, select `External`)
    - Contact Information
    - Finish (to agree to the Google API Services: User Data Policy)
    
f. Click **Create**.

# 2. Add User

a. In the left sidebar, click **Audience**.

b. Under Test users, click **+ Add users** then add the address you'll use to log into your admin dashboard.

c. Click **Save**.

# 3. Create Client

a. In the left sidebar, click **Clients**.

b. Click **+ Create client**.

c. In the **Application type** drop-down, select `Web application`.

d. Give your application a **Name**.

e. Under Authorized JavaScript origins, enter any URLs you'll use to access your application. For example:
    - Local host: `http://localhost:3000`
    - Vercel deployment: `https://<your-vercel-project-name>.vercel.app`

f. Under Authorized redirect URIs, enter your Supabase project's callback URL based on your `NEXT_PUBLIC_SUPABASE_URL`. For example:

    ```bash
    https://<your-database-url>.supabase.co/auth/v1/callback
    ```

g. Click **Create**.

h. On the OAuth client created popup, copy the **Client ID** and **Client secret** to your clipboard. Hang on to these — we'll need to enter this into Supabase to connect Google OAuth 2.0 in the next section.

    ::: {.callout}
    Click **Download JSON** to save your OAuth client credentials to a file as a backup.
    :::

:::

## Connect Supabase and Google

After you have your Google OAuth client credentials, within Supabase:


1. In the left sidebar, click **Authentication**, then select **Sign In / Providers**.

2. Under Auth Providers, click **Google**.

3. Toggle **Enable Sign in with Google** to ON.

4. Replace the **Client IDs** with your Google OAuth client ID.

5. Paste in your **Client Secret (for OAuth)**.

6. Click **Save**.
