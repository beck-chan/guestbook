# Chatbot Build

::: {.callout}

# Elasticsearch index served by Docker pulls from MDX files synced from a `guestbook` repository branch, and Gemini answers from that index.

- [`composeDocsCorpus({ forIndex: true })`](https://github.com/beck-chan/guestbook/blob/main/src/lib/docs/compose.ts){.blank} reads MDX files in [`src/app/docs`](https://github.com/beck-chan/guestbook/tree/main/src/app/docs){.blank} the same way the [inline searching](/docs/docs-build/#search-and-llm-ingestion) does.
- [`scripts/sync-docs.ts`](https://github.com/beck-chan/guestbook/blob/main/scripts/sync-docs.ts){.blank} embeds chunks and bulk-loads them into Elasticsearch.
- [`DocsChat`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/_components/DocsChat.tsx){.blank} is the [ask the documentation]{.smallcaps} bubble on every docs page that talks to [`/docs/chat`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/chat/route.ts){.blank}.

:::

## Chat Indexing

- `search: false` pages are omitted from the index (none for the local demo, usually pages under the "Internal" section are omitted). 
- `public: false` pages are still indexed — [`/docs/chat`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/chat/route.ts){.blank} applies `FLAG_PUBLIC` at query time so a public build only retrieves `public: true` chunks. 
- Inline user guide search and [`/llms.txt`](/llms.txt){.blank} keep the existing `flags.public` filter and are separate from the chatbot index.

::: {.tabset}

# compose.ts

[`src/lib/docs/compose.ts`](https://github.com/beck-chan/guestbook/blob/main/src/lib/docs/compose.ts){.blank} with `forIndex: true` builds the text that later goes into Elasticsearch:

- Reads the docs MDX files from a Git branch (`BRANCH`, default `main`).
- Shared `_snippets` files are pasted into the page that imports them, so the index stores the full wording, not an import line.
- Each chunk is marked `public: true` or `false` from the page frontmatter, so chat can filter later.
- Pages with `search: false` are left out. `public: false` pages are still included.
- A page becomes one overview chunk plus one chunk per heading (the heading's `href` may include `#anchor`).

# sync-docs.ts

[`npm run sync-docs`](https://github.com/beck-chan/guestbook/blob/main/package.json){.blank} runs [`scripts/sync-docs.ts`](https://github.com/beck-chan/guestbook/blob/main/scripts/sync-docs.ts){.blank} to embed that text and load it into Elasticsearch:

- Gemini (`gemini-embedding-001`, 768 dimensions, `RETRIEVAL_DOCUMENT`) turns each chunk into a vector for meaning search.
- The `guestbook-docs` index is deleted if it already exists, then recreated with the English analyzer on `title`, `heading`, and `body` (so “running” and “run” can match).
- Chunks and vectors are written in bulk through the Elasticsearch 8 client.
- Vectors are cached in `internal/elastic/embed-cache.json` (gitignored). Unchanged chunk text is not sent to Gemini again.

# docker-compose.es.yml

[`docker-compose.es.yml`](https://github.com/beck-chan/guestbook/blob/main/docker-compose.es.yml){.blank} serves local Elasticsearch:

- Image **8.19.7** Basic, one node, 1g heap, listening only on this machine at `127.0.0.1:9200`.
- Index data lives in the Docker volume `guestbook-es-data`, so `docker compose … down` keeps it. `down -v` wipes it.

:::

## Chatbot Interface

On first open of [`DocsChat`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/_components/DocsChat.tsx){.blank} (the [ask the documentation]{.smallcaps} / [hide chat]{.smallcaps} control), [`DocsChatPanel`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/_components/DocsChatPanel.tsx){.blank} is dynamically imported:

- Clicking **Send** posts the question to [`src/app/docs/chat/route.ts`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/chat/route.ts){.blank}, which looks up matching docs in Elasticsearch, then asks Gemini to write a summary from those excerpts only, or uses the same route to restore previous  messages from the same session.
- Clicking **Clear Chat** drops the current `docs_chat_id` cookie and the matching Supabase session, [clearing message history](#chat-history).

::: {.tabset}

# Retrieval

- Gemini (`gemini-embedding-001`, 768 dimensions, `RETRIEVAL_QUERY`) turns the question into a vector so pages can match by meaning, not only by the same words.
- Elasticsearch then runs two searches: keyword match (BM25) and meaning match (kNN). Those ranked lists are combined (RRF) so a page that does well on either can still surface.
- At most three pages are kept, and only if their combined score is close to the best hit. Weaker matches are dropped.
- Privacy Policy, Terms of Service, and Cucumber Tests are pushed down unless the question is actually about them.
- Short words such as `api` and `add` are kept for matching (three characters or more).
- If a heading on that page matches the question, that heading's excerpt is used instead of the page overview.
- When `FLAG_PUBLIC` is on, only `public: true` pages are retrieved.

# Answers

- Gemini (`gemini-3.6-flash`) writes the reply from those retrieved excerpts only — it does not read the rest of the docs.
- It answers from those excerpts even when they are brief, and only says it could not find that if they are about a different topic.
- The stream lists **Relevant Guides** (links to those pages) first, then **Summary**.
- The same browser IP is hashed and limited to 5 questions per hour and 10 per day ([`consumeDocsChatRateLimit`](https://github.com/beck-chan/guestbook/blob/main/src/lib/rate-limit.ts){.blank}).

:::

## Chat History

`docs_chat_session` and `docs_chat_message` tables in Supabase created by [`scripts/chat-history.sql`](https://github.com/beck-chan/guestbook/blob/main/scripts/chat-history.sql){.blank} store chat history per browser session. The browser never talks to these tables — row-level security is on with no `anon` / `authenticated` policies, [`/docs/chat`](https://github.com/beck-chan/guestbook/blob/main/src/app/docs/chat/route.ts){.blank} reads and writes them with the `service_role` client:

::: {.tabset}

# `docs_chat_session` 

`docs_chat_session` is one conversation — cookie `docs_chat_id` (httpOnly, path `/`) stores that row's id so opening [ask the documentation]{.smallcaps} again restores the same thread — not a login, and not shared across devices. **Clear Chat** deletes that cookie and this session row.

# `docs_chat_message` 

`docs_chat_message` is each turn in that conversation — the user's question or the assistant's reply (`role`), the wording (`content`), and for replies the retrieved page links (`sources`). Deleting a session deletes its messages.
