# Enable Notifications

::: {.callout}
This guide assumes that:

- [x] You've set up the guestbook application with either [Quickstart](/docs/quickstart) or [Install via npm](/docs/install).
- [x] (For cloud deployment) You have a Vercel account and project.

:::

When notifications are enabled, emails are sent for:

| Event | Recipients |
| --- | --- |
| New email added/invited to admin allow-list ("Admin list") | The new address, and existing admin list |
| Email removed from the admin allow-list | The removed address, and existing admin list |
| Comment submitted | Admin list |
| Admin edits or deletes a comment | Admin list |
| Guestbook settings saved | Admin list |
| Invited admin completes sign-in for the first time | The new user, and existing admin list |

## Setting Up

### Create Webhook Secret

[Supabase Edge Functions](https://supabase.com/docs/guides/functions){.blank} check a shared secret instead of a user JSON Web Token (JWT). 

We'll first generate a shared secret that will be used with our [Supabase Database Webhooks](https://supabase.com/docs/guides/database/webhooks). 

1. Use a secure password generator like [Bitwarden's password generator](https://bitwarden.com/password-generator/){.blank}:

    - Choose **Password** and not Passphrase.
    - Set the **Characters** length to `32` or longer.
    - Leave **A–Z**, **a–z**, and **0–9** on, and keep !@#$%^&* off so you can paste the value into `npx supabase secrets set` without quoting.

2. Copy the generated password. Hang on to this — we'll need to store this as Supabase secret when we connect Google OAuth 2.0 to Supabase under `NOTIFY_WEBHOOK_SECRET`:

    ```bash
    NOTIFY_WEBHOOK_SECRET=<your-webhook-secret>
    ```

::: {.callout}
# Treat your webhook secret like a password.

Anyone who gets a hold of your `NOTIFY_WEBHOOK_SECRET` can send emails as you. If it's compromised, generate a new one and update the Supabase secret and your webhooks.
:::

### Create Gmail Google Cloud Project

::: {.callout}
# Notifications are send out from your personal Gmail, not a branded domain.

- The [Supabase Edge Functions](https://supabase.com/docs/guides/functions){.blank} call the Gmail API over HTTPS, and recipients will be shown the address set in `GMAIL_USER`.
- Please note that Gmail has a low daily send limit for this type of setup, around ~100–500/day.
:::

As sending emails requires more sensitive scopes, which may delay the approval of your OAuth client if you intend to [publish the OAuth client for the admin authentication](/docs/admin#publish-your-google-oauth-client) to the general public, let's create a new project for notifications.

Log in to your [Google Cloud](https://console.cloud.google.com/){.blank} console:

::: {.tabset}

# 1. Enable Gmail API

a. [Create a new Google Cloud project](https://developers.google.com/workspace/guides/create-project){.blank}.

b. Make sure to select the project you just created by clicking **Select your project** (or the name of the guestbook project, if that is what you have currently selected).

c. In the left sidebar, click **APIs & Services**, then **Library**.

d. Under Google Workspace, select **Gmail API**.

e. Click **Enable**.

# 2. Create Client

a. In the left sidebar, click **APIs & Services**, then select **OAuth consent screen**.

b. In OAuth Overview, click **Get started**.

c. Configure your project, then click **Create**. For example, enter your:

    - App Information
    - Audience (for personal Google accounts, select `External`)
    - Contact Information
    - Finish (to agree to the Google API Services: User Data Policy)

d. Click **Create**.

e. In the left sidebar, click **APIs & Services**, then select **Credentials**.

f. Click **+ Create credentials**, then select **OAuth client ID**.

g. In the **Application type** drop-down, select `Web application`.  

h. Give your application a **Name**.

i. Click **Create**.

j. On the OAuth client created popup, copy the **Client ID** and **Client secret** to your clipboard. Hang on to these — we'll need to store these as Supabase secrets in the next section under `GMAIL_CLIENT_ID` and `GMAIL_CLIENT_SECRET`:

    ```bash
    GMAIL_CLIENT_ID=<your-client-id>.apps.googleusercontent.com
    GMAIL_CLIENT_SECRET=<your-client-secret>
    ```


    ::: {.callout}
    Click **Download JSON** to save your OAuth client credentials to a file as a backup.
    :::

# 3. Create Refresh Token

a. Open [OAuth 2.0 Playground](https://developers.google.com/oauthplayground/){.blank}.

b. Click the <DocsGear /> icon (OAuth 2.0 configuration). 

c. Check the **Use your own OAuth credentials** checkbox. 

d. Paste in your `GMAIL_CLIENT_ID` and `GMAIL_CLIENT_SECRET` from the OAuth 2.0 client you just created.

e. Click **Close**.

f. From the scope list left sidebar, open **Gmail API v1** and select `https://www.googleapis.com/auth/gmail.send`. 

h. Click **Authorize APIs**.

i. Sign in as the user that is connected to the OAuth 2.0 client you just created to allow access.

j. Click **Exchange authorization code for tokens**, then copy the **Refresh token**. 

    Hang on to this — we'll need to store these as Supabase secrets in the next section under `GMAIL_REFRESH_TOKEN`:

    ```bash
    GMAIL_REFRESH_TOKEN=<your-refresh-token>
    ```

::: {.callout}
# Treat your refresh token like a password. 

If Google revokes the refresh token, you'll need to create a new token and update the Supabase secret if mail stops.

:::

:::

### Create Supabase Access Token

From within [Supabase](https://supabase.com/):

1. Click on your profile icon in the top right corner, then select **Account**.

2. In the left sidebar, click **Access Tokens**.

3. Click **Generate new token**:

    - Enter in a **Name** for the token.
    - Set the time the token **Expires in**.

4. Scope the **Resource** access to **Project**, then under **Select projects** choose your guestbook project.

5. Under **Permissions**, select *`Preset - Read only*.

6. Click **Project**, then under **Project Settings**, select `Read`.

7. Click Application services:

    - Under **Edge Functions**, select `Read-write`.
    - Under **Edge Function Secrets**, select `Read-write`.

8. Click **Review access >**.

9. Click **Create token**.

10. Copy the token to your clipboard. Hang on to this — we'll need to store this as Supabase secret in the next section under `SUPABASE_ACCESS_TOKEN`:

    ```bash
    SUPABASE_ACCESS_TOKEN=<sbp_your_access_token>
    ```

## Customize Notification Templates

{/* ONLY EDIT HERE */}

Subject lines and body copy live as Markdown in [`supabase/functions/_shared/templates`](https://github.com/beck-chan/y2k-guestbook/tree/main/supabase/functions/_shared/templates){.blank} on the guestbook repo you deploy. Edit the files there (or in your fork), then redeploy the Edge Functions for the change to go out.

Each file is plain text with a `subject:` frontmatter block. Mail is sent as `text/plain`, so Markdown emphasis is not rendered.

```md
---
subject: New guestbook comment from {{name}}
---

{{name}} signed the guestbook.

{{body}}

Admin: {{admin}}
```

Keep the filename, the `---` fences, and the `subject:` key. Leave placeholders as `{{name}}` — the function fills them at send time.

| File | Sends when | Recipients | Placeholders |
| --- | --- | --- | --- |
| `allowlist-added-self.md` | Address added to the admin allow-list | The new address | `{{email}}`, `{{admin}}` |
| `allowlist-added.md` | Same event | Existing admin list | `{{email}}`, `{{admin}}` |
| `allowlist-removed-self.md` | Address removed from the admin allow-list | The removed address | `{{email}}`, `{{admin}}` |
| `allowlist-removed.md` | Same event | Remaining admin list | `{{email}}`, `{{admin}}` |
| `comment-insert.md` | Comment submitted | Admin list | `{{name}}`, `{{body}}`, `{{admin}}` |
| `comment-update.md` | Comment edited | Admin list | `{{name}}`, `{{body}}`, `{{admin}}` |
| `comment-delete.md` | Comment deleted | Admin list | `{{name}}`, `{{body}}`, `{{admin}}` |
| `settings-update.md` | Guestbook settings saved | Admin list | `{{summary}}`, `{{admin}}` |
| `auth-created-self.md` | Invited admin completes sign-in for the first time | The new user | `{{email}}`, `{{admin}}` |
| `auth-created.md` | Same event | Existing admin list | `{{email}}`, `{{admin}}` |

`{{admin}}` is the admin dashboard URL. Do not add extra frontmatter keys. Renaming a file means the function will not find it.

### Configure Database Webhooks

1. Within your Supabase project for the guestbook, select **Integrations** from the left sidebar.

2. From the Explore all landing page, select **Database Webhooks**.

3. Click **Install integration**.

4. Click **Install integration** again to confirm the installation.

5. Select the **Webhooks** tab. For each hook in the following list:

    ::: {.tabset}

    # 1. Notify Admins Hooks

    | Table | Events |
    | --- | --- |
    | `public.admin_allowlist` | INSERT, DELETE |
    | `public.comments` | INSERT, UPDATE, DELETE |
    | `public.guestbook_settings` | UPDATE |

    ::: {.callout}
    # Do *not* enable UPDATE on `admin_allowlist`. 

    Re-running `npm run allow-admin` for an existing address should not send a notification.

    :::

    ## 2. Admin User Authenticated Hook

    | Table | Events |
    | --- | --- |
    | `auth.users` | INSERT |

    :::

    a. Click **Create a new hook**.

    b. Enter a **Name**, such as `admin_added`.

    c. Under **Table**, select the table you want to add a hook for (you'll need to repeat these steps for each table).

    d. Set **Type of webhook** to **HTTP Request**.

    e. Then set **HTTP Request** to:

        - **Method:** `POST`
        - **URL:** `https://<your-database-url>.supabase.co/functions/v1/notify-admins`

    f. Under **HTTP Headers**, click **Add header** and add the following headers:

        | Name | Value |
        | --- | --- |
        | `Content-Type` | `application/json` |
        | `x-notify-webhook-secret` | The same string as `NOTIFY_WEBHOOK_SECRET` |

    g. Click **Create webhook**.

## Enable Notifications

Notifications are gated behind a feature flag. You'll need to set this flag to `true` in two places:

::: {.tabset}

# 1. Local Development or Deployment

To set in `.env.local` (for local development) or your Vercel [**Environment Variables**](https://vercel.com/docs/environment-variables){.blank} (for cloud deployment):

```bash
FLAG_NOTIF=true
```

# 2. Supabase Project

To set in your Supabase project for the guestbook:

```bash
npx supabase secrets set --project-ref <your-database-url> FLAG_NOTIF=true
```
