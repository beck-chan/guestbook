# Add Analytics

Use PostHog to track page views and user interactions, as well as to show a visitor hit counter in your production build.

::: {.callout}
This guide assumes:

- [x] You've set up the guestbook application with either [Quickstart](/docs/quickstart) or [Install via npm](/docs/install).
- [x] You already have a PostHog account and project.
- [x] (For cloud deployment) You have a Vercel account and project.
:::

## PostHog Setup

### Retrieve PostHog Variables

From the [PostHog](https://posthog.com/){.blank} dashboard's left sidebar, click **Settings**:

::: {.tabset}

# 1. Retrieve Project Details

 Under Settings - General:

a. Copy your **Project token**. Enter this into your `.env.local` file under your `NEXT_PUBLIC_POSTHOG_KEY`:
    
    ```bash
    NEXT_PUBLIC_POSTHOG_KEY=<your-project-token>
    ```

b. Under SDK setup, grab the `api_host` value from one of the snippets (For example, `https://us.i.posthog.com`). Enter this into your `.env.local` file under your `NEXT_PUBLIC_POSTHOG_HOST`:
    
    ```bash
    NEXT_PUBLIC_POSTHOG_HOST=<your-project-api-host>
    ```

c. Copy your **Project ID**. Enter this into your `.env.local` file under your `POSTHOG_PROJECT_ID`:
    
    ```bash
    POSTHOG_PROJECT_ID=<your-project-id>
    ```

# 2. Create Personal API Key

a. In the Settings left sidebar, select **Personal API keys** under Account.

b. Click **+ Create personal API key**.

c. Give the key a **Label**. For example: `Guestbook Hit Counter`

d. Under **Organizations & project access**, select **Projects** then the project you want to grant access to.

e. Under **Scopes**, select **Query**: `Read`.

f. Click **Create key**.

    i. Copy your API key after it generates. Enter this into your `.env.local` file under your `POSTHOG_PERSONAL_API_KEY`:

        ```bash
        POSTHOG_PERSONAL_API_KEY=<your-personal-api-key>
        ```

    ii. For your `POSTHOG_API_HOST`, enter the app host for the Query API (For example: `https://us.posthog.com`, not the `*.i.posthog.com` ingest host):

        ```bash
        POSTHOG_API_HOST=<your-api-host>
        ```

:::

### Configure PostHog

For cloud deployment:

::: {.tabset}

# 1. Enter Vercel Variables

If you are deploying to Vercel:

a. In the left sidebar of your guestbook project, select **Environment Variables**.

b. Click **Add Environment Variable**.

c. Enter the following as **Config** Type variables:

    ```bash
    NEXT_PUBLIC_POSTHOG_KEY=<your-project-token>
    NEXT_PUBLIC_POSTHOG_HOST=<your-project-api-host>
    ```

d. Enter the following as **Secret** Type variables:

    ```bash
    # IMPORTANT: MAKE SURE THEY ARE SECRET SO THEY ARE HIDDEN
    POSTHOG_PERSONAL_API_KEY=<your-personal-api-key>
    POSTHOG_PROJECT_ID=<your-project-id>
    POSTHOG_API_HOST=<your-api-host>
    ```

# 2. Configure Web Analytics URLs

a. From the PostHog dashboard's left sidebar, click **Settings**.

b. Under Products, select **Web analytics**.

c. Under **Web analytics domains**, click **+ Add new authorized URL**.

d. Enter in the URL of your deployed guestbook application. For example: `https://<your-project-url>.vercel.app`

e. Click **Save**.

:::


## Enable Hit Counter

In `env.local` (for local development) or your Vercel environment variables (for cloud deployment):

1. Toggle **`FLAG_COUNTER=`** to `true`.

2. Scope the counter to your guestbook page(s) with `FLAG_COUNTER_URL` (comma-separated for more than one). For example:

    - **Path:** `/guestbook`, or `/` if the guestbook is the home page.
    - **Full URL:** `https://example.com/guestbook` — matched as a substring of `$current_url`.
    - **Several pages:** `/guestbook,/docs/example`

    Leaving this variable empty counts all `$pageview` events on the site.

3. Optionally set **`FLAG_COUNTER_DATE=`** to a UTC instant (`YYYY-MM-DDTHH:mm:ssZ`, e.g. `2025-09-12T00:00:00Z`) so unique `$pageview` visitors are counted only at or after that time. 

    Leave it empty to count all time.

::: {.callout}
# `npm run dev` keeps the decorative fallback (`000481`) and does not call PostHog. 

Digits displayed are unique `$pageview` visitors from PostHog’s Query API. In production they live-update: — +1 on a browser’s first visit, then poll about every 45 seconds, and never tick down.

:::

## Enable Web Tracking

1. Install [`posthog-js`](https://www.npmjs.com/package/posthog-js){.blank} to enable capture of client pageviews, clicks, and session replay:

    ```bash
    npm install posthog-js
    ```

2. Copy [`instrumentation-client.ts.example`](https://github.com/beck-chan/y2k-guestbook/blob/main/instrumentation-client.ts.example){.blank} to `src/instrumentation-client.ts` (or the project root if there is no `src/`):

    ::: {.tabset}

    # Quickstart

    ```bash
    cp instrumentation-client.ts.example src/instrumentation-client.ts
    ```

    # Install with npm

    ```bash
    cp node_modules/y2k-guestbook/instrumentation-client.ts.example src/instrumentation-client.ts
    ```

    :::

    ::: {.callout}
    # Next.js only loads the exact filename `instrumentation-client.ts`. Do not paste the PostHog HTML snippet into your layout.

    The example initializes PostHog only when `NODE_ENV === "production"`, with `person_profiles: "always"` which captures pageviews, clicks, and session replay via the SDK defaults.

    :::

3. From the PostHog dashboard's left sidebar, click **Settings**.

4. Under Products, select **Session replay**. Toggle ON:

    - **Record user sessions**
    - **Log capture**
    - **Canvas capture**

## Test Hit Counter & Tracking 

Since development builds do not send tracking events, test the hit counter by building and serving the application locally:

```bash
# Linter check for errors
npm run lint
# Compile
npm run build
# Serve build 
npm run start
```

Confirm the hit counter is displaying the expected number of unique visitors for your guestbook page(s):

1. From the PostHog dashboard's left sidebar, click **Product analytics**.

2. Click **+ New**, then select **SQL**.

3. Enter in a SQL query to count the unique visitors for your guestbook page(s):

    ```sql
    # Single URL
    SELECT uniq(distinct_id)
    FROM events
    WHERE event = '$pageview'
    AND properties.$current_url LIKE '%/guestbook%' # Example slug
    AND timestamp >= toDateTime('2025-09-12 00:00:00', 'UTC') # Optional: match FLAG_COUNTER_DATE
    ```

    ```sql
    # Multiple URLs
    SELECT uniq(distinct_id)
    FROM events
    WHERE event = '$pageview'
    AND (
        properties.$current_url LIKE '<your-url-one>'
        OR properties.$current_url LIKE '<your-url-two>'
    )
    AND timestamp >= toDateTime('2025-09-12 00:00:00', 'UTC') # Optional: match FLAG_COUNTER_DATE
    ```

4. Click **Run**.

5. Confirm that the returned **Results** match your displayed hit counter.
