# MDX Reference

To build only the documentation for previewing:

```bash
npm run docs
```

::: {.callout}

Copy `example/page.tsx` next to a `content.mdx` into a directory named for the page URL slug.

Navigation with sections linked to the documentation landing page is defined in `src/app/docs/_nav/docs-nav-data.ts`.

:::

## Build Reference

Documentation is a Next App Router tree under `src/app/docs`, compiled by `@next/mdx` — not a third-party docs framework.

`next.config.ts` registers `remark-gfm`, the custom `src/lib/mdx/remark-docs-syntax.mjs` plugin (YAML frontmatter, `:::` fences, `{.heart}` / `{.button}` / `{.blank}`, TOC / title / frontmatter exports), `rehype-slug`, and `src/lib/mdx/rehype-docs-highlight.mjs`. `src/mdx-components.tsx` maps headings, tables, lists, and those fence components (`DocsCallout`, `DocsColumns`, `DocsTabset`, …) onto docs classes.

Each article page is a `page.tsx` that imports `./content.mdx` and wraps it in `DocsPage`. `src/app/docs/layout.tsx` supplies the `.docs-shell`, sidenav, and theme stylesheet. `npm run docs` starts Next with `FLAG_DOCSONLY=true` so `/` redirects into `/docs`.

### Theme

The look is `src/app/docs/docs.css`. It reuses guestbook tokens (`--peony`, `--paper`, `--peony-font`, `--body-font`, `--poem-font`) and loads Peony / Hello Honey with `font-display: block`. Article pages get a paper sidenav and a sticky-note table of contents. The landing page is a different shell: `.docs-shell:has(.docs-index)` hides the sidenav, centers the main column, and restyles `.docs-toc` as the large rotated notes.

The API page is a third shell (`.docs-api-reference` widens the sidenav and skips `DocsPage`).

### Landing Page

`/docs` is `src/app/docs/page.tsx` — React, not MDX. It reads `DOCS_NAV_SECTIONS` from `_nav/docs-nav-data.ts`, keeps Installation / Guides / Reference as notes, and turns Etc. / Support into footer links. The subtitle comes from `docsIndexSubtitle` in `src/lib/flags.ts` (the extra asterisk line is private-build only). Wrapping the tree in `.docs-index` is what switches the layout.

```tsx
const LANDING_TITLES = new Set(["Installation", "Guides", "Reference"]);

const sections = DOCS_NAV_SECTIONS.filter((section) =>
  LANDING_TITLES.has(section.title),
);
```

### Additional Landing Pages

Copy that page to a new slug (for example `src/app/docs/guides/page.tsx`) and keep the `.docs-index` wrapper so the same CSS applies. Filter a different subset of `DOCS_NAV_SECTIONS` — or extract a shared component that takes section titles and footer titles.

::: {.callout}

Do not wrap a landing in `DocsPage`. That helper is for MDX articles (sticky-note TOC + `.docs-article`). A landing only needs the `.docs-index` class on a React tree.

:::

Desktop rotation is hard-coded for three notes (`nth-child(1–3)` in `docs.css`). More than three notes needs extra rules; mobile already uses odd / even. Add the route to `docs-nav-data.ts` if it should appear in the sidenav on article pages.

## Single-Sourcing

Shared prose lives in `_snippets/`. Import a snippet to use it on a page:

```markdown
import Example from "../_snippets/example.mdx"

<Example />
```

::: {.callout}
<Example />
:::

Leave YAML and `# h1` on the host page. Snippet `##` / `###` headings are included in the host table of contents automatically, in the order the snippet appears on the page.

### Conditional Content

`public: false` in YAML hides an entire page when `FLAG_PUBLIC=true`. Leave it off and the page will display in both builds. 

To swap a chunk, not the page, use a fence — copy outside fences is always shown regardless of flags.  The other fence is dropped at compile time, including its headings. 

- `{.public}` is kept when `FLAG_PUBLIC=true`
- `{.private}` is kept when `FLAG_PUBLIC=false`


```markdown
::: {.public}
Public-build copy (`FLAG_PUBLIC=true`).
:::

::: {.private}
Custom-install copy (`FLAG_PUBLIC=false`).
:::
```

::: {.callout}

::: {.private}
This sentence is the private variant — compiled in when `FLAG_PUBLIC=false`.
:::

::: {.public}
This sentence is the public variant — compiled in when `FLAG_PUBLIC=true`.
:::

:::

For longer or generated copy, keep a sibling pair next to the host file and embed it. Shared `_snippets` imports are not rewritten. `.ts`, `.sql`, and `.feature` siblings render as a highlighted code block. 

- Unmarked `name.mdx` is the private file
- `name-public.mdx` is the public file

A missing pair file fails the build. 


```markdown
::: {.embed src="conditional-embed"}
:::
```

::: {.callout}

::: {.embed src="conditional-embed"}
:::

:::

`src` is relative to the file that contains the fence. Headings inside an embedded `.mdx` join the host table of contents.

### Tables

Pipe tables use a header row, a `| --- |` separator, and body rows:

| Data | Who | Purpose |
| --- | --- | --- |
| Display name and message body | Anyone who posts | Show guestbook comments |
| Optional email (if the email field is enabled) | Comment authors | Visible to site admins only |
| IP address (stored hashed) | Comment submitters | Rate-limit abuse |

Align a column with `:---` (left), `:---:` (center), or `---:` (right) in the separator row.
