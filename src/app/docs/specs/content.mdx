# Cucumber Specs

The `.feature` files on this page are Gherkin specifications. Use [cucumber.js](https://github.com/cucumber/cucumber-js){.blank} to run these `.feature` scenarios against your installation of the guestbook:

- A `.feature` file says what should happen. 
- A step definition is how TypeScript that actually applies the behaviour. 

::: {.callout}
- [x] This guide assumes that you've set up the guestbook application with either [Quickstart](/docs/quickstart) or [Install via npm](/docs/install).
:::

## Install Cucumber and Playwright

To install Cucumber and [Playwright](https://playwright.dev){.blank} in your app, call the following commands in your terminal from your Next.js app root:

```bash
npm install --save-dev @cucumber/cucumber playwright tsx
npx playwright install chromium
```

- `@cucumber/cucumber` — Reads `.feature` files and reports pass/fail behaviour.
- `playwright` — Drives Chromium against the running app.
- `tsx` — Loads TypeScript step definitions without a separate compile step.

::: {.callout}
# `npx playwright install chromium` downloads the browser binary once. 

Re-run it after upgrading Playwright.

:::

## Feature Directory Setup

The guestbook repository and includes the following Cucumber setup files covered in this section.

### Environment

::: {.tabset}

# cucumber.yaml

At the project root lives `cucumber.yaml` which configures Cucumber:

```yaml
default:
  paths:
    - features/**/*.feature
  requireModule:
    - tsx/cjs
  require:
    - features/support/**/*.ts
    - features/step_definitions/**/*.ts
  format:
    - progress-bar
    - html:features/reports/results.html
  formatOptions:
    snippetInterface: async-await
  worldParameters:
    baseUrl: http://localhost:3000
```

# features/support/world.ts

Cucumber needs a Playwright page on the World object so every step can click the same browser:

```typescript
import {
  IWorldOptions,
  setWorldConstructor,
  World,
} from "@cucumber/cucumber";
import type { Browser, BrowserContext, Page } from "playwright";

export class PlaywrightWorld extends World {
  browser!: Browser;
  context!: BrowserContext;
  page!: Page;
  baseUrl: string;
  postedName?: string;

  constructor(options: IWorldOptions) {
    super(options);
    const fromEnv = process.env.BASE_URL;
    const fromConfig = options.parameters.baseUrl;
    this.baseUrl = String(fromEnv ?? fromConfig ?? "http://localhost:3000").replace(
      /\/$/,
      "",
    );
  }
}

setWorldConstructor(PlaywrightWorld);
```

# features/support/hooks.ts

Hooks start Chromium, allowing page clicks on each scenario's fresh page, then closes the page when the scenario completes:

```typescript
import { After, AfterAll, Before, BeforeAll } from "@cucumber/cucumber";
import { chromium, type Browser } from "playwright";
import { PlaywrightWorld } from "./world";

let browser: Browser;

BeforeAll(async function () {
  browser = await chromium.launch({
    headless: process.env.HEADED !== "1",
  });
});

Before(async function (this: PlaywrightWorld) {
  this.browser = browser;
  this.context = await browser.newContext({
    viewport: { width: 1280, height: 720 },
  });
  this.page = await this.context.newPage();
});

After(async function (this: PlaywrightWorld) {
  await this.context.close();
});

AfterAll(async function () {
  await browser.close();
});
```

### Step Definitions

Step definitions under `features/step_definitions/` map each `Given` / `When` / `Then` to clicks in the browser. There should be step definitions for the functionality that ships with the guestbook repository, but you will need to write step definitions for any additional functionality you add.

If a `Given` / `When` / `Then` already has a matching function, Cucumber runs that function. Stubs are returned in the terminal console for Gherkin lines with no match. For example:

```typescript
Given('a user is on the guestbook page', async function () {
  // Write code here that turns the phrase above into concrete actions
  return 'pending';
});
```

Create a file in `features/step_definitions/`, paste the stub into it, and fill in the body with the appropriate code to execute the step. Instruction should be written the way a human user would find things on the page — for example, reference the `submit` button, the `display name` field, the `prev` / `next` links, and not CSS class names or code.

- It doesn't matter what the file is called, as long as it's in the `features/step_definitions/` directory and has the `.ts` extension.
- Stash values you will need later on the World object (for example `this.postedName`).


::: {.callout}
# Example Functions

| Function | Description |
| --- | --- |
| `this.page.goto(url)` | Open a page. Build the URL from `this.baseUrl` so the same steps work on `localhost` and a deployed site. |
| `this.page.getByLabel("display name").fill(text)` | Type into a field by its visible name (`display name`). |
| `this.page.getByRole("button", { name: "submit" }).click()` | Role is the kind of control (`button`, `link`). Name is the text on it (`submit`, `prev`, `next`). |
| `this.page.locator('textarea[name="comment"]').fill(text)` | Reach a field that has no visible label. Use name or role over CSS class names. |
| `locator.waitFor()` and `assert.match(await locator.innerText(), /…/)` | Wait until the result is on the page, then fail the step if the visible text does not match. |
| `this.page.setViewportSize({ width, height })` | Shrink the window *before* `goto` when the Gherkin line says *on mobile*. |

:::


## Running Cucumber Tests

::: {.tabset}

# Default Reports

A passing test run writes `features/reports/results.html` by default:

- Reruns will overwrite the file. 
- You can change the output directory by modifying the `formatOptions` in `cucumber.yaml`.

To write to a another file and the default at the same time, pass in `--format html:<filepath>`:

```bash
npx cucumber-js --format html:features/reports/guestbook.html
```

# Custom Reports

To write a different report *without* replacing the default `results.html`, add a named profile in `cucumber.yaml`. Profiles replace `default` entirely — copy the same `paths`, `requireModule`, `require`, and `worldParameters` keys, and change only the `html:` path. 

To run a profile, use the `-p` flag. For example, the `guestbook` profile already in `cucumber.yaml`:

```bash
npx cucumber-js -p guestbook
```

That writes `features/reports/guestbook.html` and leaves `results.html` alone.

### Set Up Admin Testing

Cucumber cannot finish Google's login screen on its own, so you will need to run a special session to log your authorized admin user in, then save the session once in order for subsequent runs to reuse it.

1. Start the guestbook preview server: `npm run dev`

2. In a second terminal at the app root, call:

    ```bash
    npm run save-admin-session
    ```

3. Sign in with your admin user. 

    When `/admin` loads, the script writes `features/support/.auth/admin.json` (already excluded from tracking by`.gitignore`).

::: {.callout}
# After that, `npx cucumber-js` loads that file in `hooks.ts` when it exists, so you skip the Google prompt.

Re-run `npm run save-admin-session` if the session expires or Google asks you to log in again.

:::

### Run `.feature` Tests

1. Start the guestbook preview server: `npm run dev`

2. In a second terminal at the app root, call:

::: {.tabset}

# To Run All  `.feature` Tests

```bash
npx cucumber-js
```

# To Run One  `.feature` Test

For example, the `guestbook-comments.feature` file:

```bash
npx cucumber-js features/guestbook-comments.feature
```

:::

### Optional Prefixes

::: {.tabset}

# Watch a Run

By default, Playwright hides the browser window. To watch a run:

```bash
HEADED=1 npx cucumber-js
```

# Test a Deployed URL

To hit a deployed URL instead of localhost:

```bash
BASE_URL=https://<your-deployed-url>.vercel.app npx cucumber-js
```

:::
