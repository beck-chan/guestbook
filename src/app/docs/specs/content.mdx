# Cucumber Specs

The `.feature` files on this page are Gherkin specifications. Use [cucumber.js](https://github.com/cucumber/cucumber-js){.blank} to run these `.feature` scenarios against your installation of the guestbook:

- A `.feature` file says what should happen. 
- A step definition is how TypeScript that actually applies the behaviour. 

::: {.callout}
- [x] This guide assumes that you've set up the guestbook application with either [Quickstart](/docs/quickstart) or [Install via npm](/docs/install).
:::

## Install Cucumber and Playwright

To install Cucumber and Playwright in your app, call the following commands in your terminal from your Next.js app root:

```bash
npm install --save-dev @cucumber/cucumber playwright tsx
npx playwright install chromium
```

- [`@cucumber/cucumber`](https://www.npmjs.com/package/@cucumber/cucumber){.blank} — Reads `.feature` files and reports pass/fail behaviour.
- [`playwright`](https://www.npmjs.com/package/playwright){.blank} — Drives Chromium against the running app.
- [`tsx`](https://www.npmjs.com/package/tsx){.blank} — Loads TypeScript step definitions without a separate compile step.

Confirm your installations by running:

```bash
npm ls @cucumber/cucumber playwright tsx
```

::: {.callout}
# `npx playwright install chromium` downloads the browser binary once. 

Re-run it after upgrading Playwright.

:::

## Cucumber Setup

The guestbook repository includes [`cucumber.yaml`](https://github.com/beck-chan/y2k-guestbook/blob/main/cucumber.yaml){.blank} at the project root and the TypeScript helpers in [`features/support/`](https://github.com/beck-chan/y2k-guestbook/tree/main/features/support){.blank}. 

### cucumber.yaml

[`cucumber.yaml`](https://github.com/beck-chan/y2k-guestbook/blob/main/cucumber.yaml){.blank} tells Cucumber which `.feature` files to run, which TypeScript to load, and provides the default application URLs:

```yaml
default:
  requireModule:
    - tsx/cjs
  require:
    - features/support/**/*.ts
    - features/step_definitions/**/*.ts
  format:
    - progress-bar
    - html:features/reports/results.html
  formatOptions:
    snippetInterface: async-await
  worldParameters:
    baseUrl: http://localhost:3000
    guestbookPath: /
    adminPath: /admin

admin:
  requireModule:
    - tsx/cjs
  require:
    - features/support/**/*.ts
    - features/step_definitions/**/*.ts
  format:
    - progress-bar
    - html:features/reports/admin.html
  formatOptions:
    snippetInterface: async-await
  worldParameters:
    baseUrl: http://localhost:3000
    guestbookPath: /
    adminPath: /admin
```

# `world.ts`

[`features/support/world.ts`](https://github.com/beck-chan/y2k-guestbook/blob/main/features/support/world.ts){.blank} sets up a Playwright page on the world object so that every step can click the same browser:

```typescript
import { config } from "dotenv";
import { setWorldConstructor, World } from "@cucumber/cucumber";
import type { Browser, BrowserContext, Page } from "playwright";

config({ path: ".env.local" }); // BASE_URL, paths, and the Supabase keys seed.ts uses

export class PlaywrightWorld extends World {
  browser!: Browser;
  context!: BrowserContext;
  page!: Page; // every Given / When / Then in this scenario uses this page
  baseUrl: string;
  guestbookPath: string;
  adminPath: string;
  postedName?: string; // stash in one step, read in a later Then (the comment you just posted)

  constructor(options) {
    super(options);
    // cucumber.yaml worldParameters, overridable with BASE_URL / GUESTBOOK_PATH / GUESTBOOK_ADMIN_PATH
    this.baseUrl = String(process.env.BASE_URL ?? options.parameters.baseUrl ?? "http://localhost:3000");
    this.guestbookPath = String(process.env.GUESTBOOK_PATH || process.env.NEXT_PUBLIC_GUESTBOOK_PATH || options.parameters.guestbookPath || "/");
    this.adminPath = String(process.env.GUESTBOOK_ADMIN_PATH || process.env.NEXT_PUBLIC_GUESTBOOK_ADMIN_PATH || options.parameters.adminPath || "/admin");
  }

  guestbookUrl() {
    return this.guestbookPath === "/" ? this.baseUrl : `${this.baseUrl}${this.guestbookPath}`;
  }

  adminUrl() {
    return `${this.baseUrl}${this.adminPath}`;
  }
}

setWorldConstructor(PlaywrightWorld);
```

::: {.callout}
# Changed Paths

If your guestbook doesn't live at the root of your domain (`/`) or the admin dashboard is not at `/admin`:

- Ensure your `NEXT_PUBLIC_GUESTBOOK_ADMIN_PATH` and `GUESTBOOK_PATH` `.env.local` variables match your custom paths so that step definitions navigate using the correct `this.guestbookPath` / `this.adminPath`.
- Keep the Gherkin wording as written (`/admin`). 

:::

# `hooks.ts`

[`features/support/hooks.ts`](https://github.com/beck-chan/y2k-guestbook/blob/main/features/support/hooks.ts){.blank} starts Chromium, gives each scenario a fresh page, and resets data so one run does not leak into the next:

```typescript
import { After, AfterAll, Before, BeforeAll } from "@cucumber/cucumber";
import { chromium, type Browser } from "playwright";
import { PlaywrightWorld } from "./world";
import { resetGuestRateLimits, restoreDefaultSettings } from "./seed";

let browser: Browser;

BeforeAll(async function () {
  // HEADED=1 shows the window so you can finish Google's login screen
  browser = await chromium.launch({ headless: process.env.HEADED !== "1" });
});

Before(async function (this: PlaywrightWorld, { pickle }) {
  this.browser = browser;
  this.context = await browser.newContext({ viewport: { width: 1280, height: 720 } });
  this.page = await this.context.newPage();
  // After one headed admin sign-in, later admin runs reuse features/support/.auth/admin.json
  // Guest / unauthorized features use a second Chromium so they cannot reuse that admin cookie
  if (pickle.uri.includes("guestbook")) await resetGuestRateLimits();
});

After(async function (this: PlaywrightWorld, { pickle }) {
  // admin-settings.feature writes title / fonts / page size — put the defaults back
  if (pickle.uri.includes("admin-settings")) await restoreDefaultSettings();
  await this.context.close();
});

AfterAll(async function () {
  await browser.close();
});
```

# `ui.ts`

[`features/support/ui.ts`](https://github.com/beck-chan/y2k-guestbook/blob/main/features/support/ui.ts){.blank} holds the shared locators so step definitions click visible names (`submit`, `display name`) instead of copying CSS class names:

```typescript
import type { Page } from "playwright";
import type { PlaywrightWorld } from "./world";

export async function openGuestbook(world: PlaywrightWorld) {
  await world.page.goto(world.guestbookUrl(), { waitUntil: "domcontentloaded" });
  await world.page.getByRole("button", { name: "submit" }).waitFor();
}

export async function fillGuestComment(
  page: Page,
  input: { name: string; body: string },
) {
  await page.getByLabel("display name").fill(input.name);
  await page.locator('textarea[name="comment"]').fill(input.body);
}

export async function clickSubmit(page: Page) {
  await page.getByRole("button", { name: "submit" }).click();
}
```

# `seed.ts`

[`features/support/seed.ts`](https://github.com/beck-chan/y2k-guestbook/blob/main/features/support/seed.ts){.blank} writes to the database when a scenario needs rows already on the board, or when hooks need to undo a previous run:

```typescript
import { createClient } from "@supabase/supabase-js";
import { Pool } from "pg";

// Service role — Cucumber can insert comments without going through the form
export function serviceClient() {
  return createClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.SUPABASE_SERVICE_ROLE_KEY!,
  );
}

export async function seedComment(body: string) {
  // Gherkin that needs existing comments (pagination, admin filters)
  return serviceClient()
    .from("comments")
    .insert({ display_name: "cucumber", body })
    .select()
    .single();
}

export async function resetGuestRateLimits() {
  // hooks.ts runs this before guestbook features (needs DATABASE_URL)
  const pool = new Pool({ connectionString: process.env.DATABASE_URL });
  await pool.query("delete from guestbook_rate_limits");
  await pool.end();
}

export async function restoreDefaultSettings() {
  // hooks.ts runs this after admin-settings.feature
  await serviceClient().from("guestbook_settings").update({ /* defaults */ }).eq("id", 1);
}
```

## Running Cucumber Tests

::: {.tabset}

# Default Reports

A passing test run writes `features/reports/results.html` by default:

- Reruns will overwrite the file. 
- You can change the output directory by modifying the `formatOptions` in `cucumber.yaml`.

To write to a another file and the default at the same time, pass in `--format html:<filepath>`:

```bash
npx cucumber-js --format html:features/reports/guestbook.html
```

# Custom Reports

To write a different report *without* replacing the default `results.html`, add a named profile in `cucumber.yaml`. Profiles replace `default` entirely — copy the same `requireModule`, `require`, and `worldParameters` keys, and change the `paths` and `html:` values.

To run a profile, use the `-p` flag. For example, the `admin` profile already in `cucumber.yaml`:

```bash
# Run with browser visible
HEADED=1 npx cucumber-js -p admin
```

That writes `features/reports/admin.html` and leaves `results.html` alone.

These tests do not require any admin authentication, so they can be run without any additional setup.

1. Start the guestbook preview server: `npm run dev`

2. In a second terminal at the app root, call:

## Write Additional Tests

If a `Given` / `When` / `Then` already has a matching function, Cucumber runs that function. Stubs are returned in the terminal console for Gherkin lines with no match. For example:

```typescript
Given('a user is on the guestbook page', async function () {
  // Write code here that turns the phrase above into concrete actions
  return 'pending';
});
```

Create a file in `features/step_definitions/`, paste the stub into it, and fill in the body with the appropriate code to execute the step. Instruction should be written the way a human user would find things on the page — for example, reference the `submit` button, the `display name` field, the `prev` / `next` links, and not CSS class names or code.

- It doesn't matter what the file is called, as long as it's in the `features/step_definitions/` directory and has the `.ts` extension.
- Stash values you will need later on the World object (for example `this.postedName`).


::: {.callout}
# Example Functions

| Function | Description |
| --- | --- |
| `this.page.goto(url)` | Open a page. Build the URL from `this.baseUrl` so the same steps work on `localhost` and a deployed site. |
| `this.page.getByLabel("display name").fill(text)` | Type into a field by its visible name (`display name`). |
| `this.page.getByRole("button", { name: "submit" }).click()` | Role is the kind of control (`button`, `link`). Name is the text on it (`submit`, `prev`, `next`). |
| `this.page.locator('textarea[name="comment"]').fill(text)` | Reach a field that has no visible label. Use name or role over CSS class names. |
| `locator.waitFor()` and `assert.match(await locator.innerText(), /…/)` | Wait until the result is on the page, then fail the step if the visible text does not match. |
| `this.page.setViewportSize({ width, height })` | Shrink the window *before* `goto` when the Gherkin line says *on mobile*. |

:::
