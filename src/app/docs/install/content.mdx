## Check Dependencies

Ensure you have your required dependencies, which Next.js and React should already satisfy:

- [x] [`next`](https://www.npmjs.com/package/next){.blank} (App Router *only* — Pages Router is not supported.)
- [x] [`react`](https://www.npmjs.com/package/react){.blank} and [`react-dom`](https://www.npmjs.com/package/react-dom){.blank}
- [x] [`@supabase/supabase-js`](https://www.npmjs.com/package/@supabase/supabase-js){.blank}
- [x] [`@supabase/ssr`](https://www.npmjs.com/package/@supabase/ssr){.blank} (cookie sessions for Google admin login)

From your terminal at your application project root run:

```bash
npm ls next react react-dom @supabase/supabase-js @supabase/ssr
```

::: {.callout}

That is fine for the Supabase packages — install them in the next step. 

If `next`, `react`, or `react-dom` are missing, add them (or scaffold with `create-next-app`) before continuing.

## Installing

### Install Guestbook Package

From your existing Next.js app root, install `y2k-guestbook` from GitHub:

```bash
npm install y2k-guestbook@github:beck-chan/y2k-guestbook @supabase/supabase-js @supabase/ssr
```

### Set Up Environment Variables

1. Copy the `.env.example` file to `.env.local`:

    ```bash
    cp node_modules/y2k-guestbook/.env.example .env.local
    ```

## Configuring the Application

### Protect Admin Login

Next only runs auth/session files from *your* project. Add three small files. Put `proxy.ts` next to `app/` (repository root, or `src/proxy.ts` if you use `src/app`) — not inside `app/`.

::: {.tabset}

# 1. Proxy

Create `proxy.ts` to keep the Supabase session fresh and block the admin path (default `/admin`) unless `app_metadata.role === "admin"`. Next needs `config.matcher` as a constant in *this* file:

```typescript
export { proxy } from "y2k-guestbook/proxy";

export const config = {
  matcher: [
    "/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp|css)$).*)",
  ],
};
```

- The **admin login** link stays visible, but users without proper access are booted back to the 
public guestbook comment board and presented with an error.
- Error message copy is hardcoded in [`src/components/_shared/AdminAuthErrorOverlay.tsx`](https://github.com/beck-chan/y2k-guestbook/blob/main/src/components/_shared/AdminAuthErrorOverlay.tsx){.blank} — not accessible through the admin dashboard settings.

::: {.callout}

If you already have a `proxy.ts`, import `{ proxy as guestbookProxy }` from `y2k-guestbook/proxy` and call it from your existing `proxy` function instead of replacing the file. Keep `/auth/callback` and the admin login path reachable (`${admin}/login`, default `/admin/login`).

:::

# 2. Route

Create the login route at the default path `app/admin/login/route.ts` (or under your custom admin directory — refer to [Add Guestbook Pages: Admin Dashboard](#add-guestbook-pages) below):

```typescript
export { GET } from "y2k-guestbook/admin-login";
```

Clicking **admin login** sends you to Google sign-in. After authenticating, you return to the your configured `${SITE_URL}/auth/callback`.

# 3. Callback

Create `app/auth/callback/route.ts`, which finishes login and sends you to the right page after Google:

```typescript
export { GET } from "y2k-guestbook/callback";
```

:::

### Add Guestbook Pages

Next only serves pages from *your* `app/` directory. Re-export the packaged entrypoints:

::: {.tabset}

# 1. Add Comment Board

a. Create `page.tsx` for your public guestbook comment board where you want it to live:

  ```typescript
  export {
    GuestbookPublicPage as default,
    guestbookPublicMetadata as metadata,
  } from "y2k-guestbook";
  ```

b. Set `NEXT_PUBLIC_GUESTBOOK_PATH` in `.env.local` according to where your public comment board lives (no trailing slash). 

  Default is the root of your domain (`/`):

  - `app/page.tsx` — When the guestbook *is* the site, omit the variable (or set `NEXT_PUBLIC_GUESTBOOK_PATH=/`).
  - `app/guestbook/page.tsx` — When `/` (root) is already your site, set `NEXT_PUBLIC_GUESTBOOK_PATH=/guestbook`.


# 2. Add Admin Dashboard

- To host your admin dashboard at the default path (`/admin`), create `app/admin/page.tsx`:

  ```typescript
  export {
    GuestbookAdminPage as default,
    guestbookAdminMetadata as metadata,
  } from "y2k-guestbook";
  ```

- To customize the path for the admin dashboard (for example `/guestbook/admin`):

  a. Set `NEXT_PUBLIC_GUESTBOOK_ADMIN_PATH=/guestbook/admin` in `.env.local` (no trailing slash).

  b. Create the following re-exports under that directory:

      - `app/guestbook/admin/page.tsx` — Your admin dashboard page.
      - `app/guestbook/admin/login/route.ts` — The admin login route. Refer to [Protect Admin Login: Route](#protect-admin-login) for more details.
      - `app/guestbook/admin/example/route.ts` — The theme example route. Refer to [Configure Next.js: 2. Set Theme Example Route](#configure-nextjs) for more details.

  ::: {.callout}
  Note that `/auth/callback` does not need to be changed even if you change `/admin` paths.

  :::

:::

## Configure Next.js

::: {.tabset}

# 1. Wrap Config

`withGuestbookConfig` adds `transpilePackages` so Next can compile the GitHub-installed package, externalizes `pg` for rate limiting, and rewrites the **view example** CSS URL. It reads `NEXT_PUBLIC_GUESTBOOK_ADMIN_PATH` for that rewrite (default `/admin/example.css`).

In your `next.config.ts` (or `next.config.js`), wrap your existing config with `withGuestbookConfig`:

```typescript
import type { NextConfig } from "next";
import { withGuestbookConfig } from "y2k-guestbook/config";

const nextConfig: NextConfig = {
  // your existing options
};

export default withGuestbookConfig(nextConfig);
```

::: {.callout}  
# If you already define your own `rewrites()`, merge them carefully — `withGuestbookConfig` adds one rewrite of its own. 

- Next, React, and React DOM must come from *your* app (`peerDependencies`). 
- If `node_modules/y2k-guestbook/node_modules/next` exists after install, delete `node_modules` and reinstall so you are not type-checking two copies of Next.

:::

# 2. Set Theme Example Route

Create `app/admin/example/route.ts` (or `app/guestbook/admin/example/route.ts` if you set a custom admin path): 

```typescript
export { GET } from "y2k-guestbook/example-css";
export const dynamic = "force-static";
```

Next cannot statically parse `dynamic` if it is re-exported from the package — declare it in this file. This is the route that **view example** loads, and it only works after the config wrapping.

# 3. Add Stylesheet and Providers

Place two last pieces in your root layout (`app/layout.tsx`):

a. Import `y2k-guestbook/styles.css` to apply the default look for the comment board and admin dashboard.

b. Wrap `{children}` in `GuestbookProviders` to display the error dialogue when someone signs in with a Google account that is not on the admin list.

```typescript
import type { Metadata } from "next";
import "y2k-guestbook/styles.css";
import { GuestbookProviders } from "y2k-guestbook";

export const metadata: Metadata = {
  title: "y2k guestbook",
  description: "Sign the guestbook.",
};

export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    <html lang="en" className="h-full antialiased">
      <body className="min-h-full">
        <GuestbookProviders>{children}</GuestbookProviders>
      </body>
    </html>
  );
}
```

::: {.callout}
# Keep your existing `globals.css` / Tailwind import for the rest of your application.

- Guestbook styles only apply to guestbook pages — the rest of your app keeps your own styling.
- You do not need to add wrappers for settings or custom CSS — guestbook pages load those themselves.
